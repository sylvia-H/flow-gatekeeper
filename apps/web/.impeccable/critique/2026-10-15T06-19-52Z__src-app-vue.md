## Design Specificity Verdict

**LLM assessment：品類可互換。** 左 sidebar 清單、中央 auto-fill 卡片網格、卡片內 2×2 指標、右側常駐面板、底部 event log、左下比例條，是 Grafana／Datadog／admin template 的預設骨架；換掉 logo 就是一個 IoT 溫控 SaaS。token 紀律很好（零散落 hex、色階一致），所以它「乾淨但無個性」——連貫性來自克制，不是來自主張。真正為本產品而作的只有三處：越界指標單獨染色、由里程碑衍生的步驟清單、AI 指令審閱警語。四個產品機制全部錯過：背壓比值在預設畫面不存在；逐字串流看起來像 worker log；Cached 只是 11px pill、沒有「秒回」的時間證據；「致敬 Argo CD」只剩狀態點加 pill，`PREP → FORMING & BAKING → FULFILMENT` 明明是一條產線，主畫面卻是無序網格。

**Deterministic scan：** 原始碼 2 筆、live URL 23 筆。
- `undersized-ui-text` ×22（URL）：所有 10px 文字——卡片狀態徽章 HEALTHY／WARNING、單位 °C／mm/s／u/min、Fleet Health `total 5`、Event Stream `3/50`。偵測器與設計審查一致：單位在 22px 數字旁幾乎讀不到。這是 `text-2xs` token 本身的問題，不是個別元件。
- `codex-grid-background` ×1（`TopologyCanvas.vue:72`）：3.5% 白色格線。偵測器允許真正的 canvas／measurement 表面，但截圖中格線幾乎不可見，是無效裝飾，判為「低價值」而非誤報。
- `side-tab` ×1（`SuggestedActionList.vue:30` 的 `border-l-2`）：AI 建議卡的左色條。單獨看是常見的 AI-slop 樣式，改版時順手處理即可，不列優先。
- 偵測器沒抓到、設計審查抓到的：背壓徽章被藏、平板重疊、資訊順序、狀態無記憶——這些都是結構問題，偵測器本來就看不到。
- 偵測器只掃了首頁，完成態 drawer 的 10px 標籤（evidence 來源 chip、步驟百分比）未計入，實際 undersized 數量更多。

**Visual overlays：** 未注入（本 session 無原生瀏覽器工具），以 11 張截圖代替。

## Overall Impression

一個工程紀律很好、但把自己的賣點藏起來的監控台。高頻更新下版面不抖、狀態誠實、token 乾淨，這些都是真功夫；可是打開畫面的人看不到背壓、看不懂串流、感覺不到快取，而且三秒就消失的 critical 沒有任何痕跡。單一最大機會：把背壓比值從 toolbar 的一顆 pill 變成整個監控台頂端那條會跳的心跳線，這一刀下去它就不再像任何其他 dashboard。

## What's Working

1. **越界指標單獨染色加多重狀態編碼。** Press 02 critical 時 Temp 97.0、Vibration 2.19、Errors 16.0 變紅而 Throughput 73 維持白色，一眼知道「哪個指標」出事；暗紅底、CRITICAL 文字徽章、StatusLight aria-label 同時滿足不只靠顏色。這是整個介面最為產品而作的決定。
2. **高頻下的版面穩定性。** 機器值一律 JetBrains Mono、千分位、單位分開渲染；stale 只降透明不清空；StatusLight 固定 12px 外框讓 pulse 不造成 layout shift。每秒數十筆更新的數字不抖，是工程紀律直接轉成的視覺品質。
3. **診斷狀態機誠實且有出口。** 四態各有明確介面；active 有中止、failed 有 Retry 與中斷前推理；live region 只在同一 job 轉態時公告；AI 指令附警語。系統做不到的事直接標出來。

## Priority Issues

**[P0] 背壓比值在預設畫面被隱藏**
- What：`TopBar.vue` 把 `BackpressureBadge` 包在 `.tb-optional`，`@container (max-width: 820px)` 整組隱藏。1440 開 drawer、1024 平板、手機都看不到；只有收起 Copilot 才出現，而且是一顆 `text-xs` pill 與 Mock Hz、Connected 同重量。
- Why：PRODUCT.md 明載這是核心賣點與 Principle 3「可見、可驗收」；評估者在 22 秒 demo 裡看不到它，等於賣點不存在。
- Fix：把背壓移出 toolbar，佔用目前只放「Fleet monitor · 5 machines」的 45px 標題列，改成常駐 pipeline strip：`received msgs/s → rendered frames/s`、22px mono 的 `7:1`、60 秒 sparkline（msgs/s 與 frames/s 兩條線）、dropped 用 warn-fg 小字。任何斷點不得隱藏，窄螢幕至少保留比值數字。
- 建議指令：`/impeccable layout`、`/impeccable bolder`

**[P1] 完成態結果的資訊順序與信號互相打架**
- What：順序 Summary → Likely causes → Evidence → Suggested actions；Evidence 不收合，8 張卡把 actions 推出首屏，5 張 ERROR LOG 只差時間戳；完成時一律畫滿版綠色 ProgressBar，即使 severity 是 Warning；結果沒有產生時間。
- Why：操作者要的是「該做什麼」，卻要捲兩屏；綠條配 Warning 傳達錯誤安全感；沒時間戳無法跟還在跳的即時卡片對照（summary 自己寫「儘管目前遙測顯示健康」）。
- Fix：順序改為 Summary + severity → Suggested actions → Likely causes → Evidence；Evidence 預設 2 筆加 `+6 more`；同來源同模式的 errorlog 合併成一列（`healthy → critical ×5，最近 06:10:56Z`）；完成態移除 ProgressBar，換一行 mono meta `Diagnosed 14:11:03 · 8.2s`，Cached 時 `Cached · 14ms`；severity 決定 drawer 頂部 2px 色條。
- 建議指令：`/impeccable distill`、`/impeccable layout`

**[P1] 逐字串流以 raw JSON 呈現，Cached 沒有「秒回」證據**
- What：`StreamingPanel` 把 streamText 原樣 pre-wrap 輸出 JSON；Cached 只是 11px pill。
- Why：這兩個是 demo 的情緒高點，現在一個像 debug log、一個幾乎看不見。
- Fix：前端用容錯 partial-JSON parser 漸進解析 token，邊串流邊把 summary／likelyCauses／suggestedActions 填進與完成態相同的骨架，游標停在正在填的欄位；raw token 改成可展開的 Raw stream 分頁（契約不變）。Cached 由前端量測 POST 到 ai/done 的耗時，mono 大字 `14 ms` 與上一次非快取耗時並列（`vs 8.2 s`），整塊直接出現、不走串流動畫。
- 建議指令：`/impeccable clarify`、`/impeccable animate`、`/impeccable delight`

**[P1] 異常與診斷狀態沒有「記憶」，網格與 sidebar 都不承載狀態**
- What：mock 尖峰幾秒就回 healthy（desktop-live 的 Press 02 CRITICAL，幾秒後 desktop-selected 已 HEALTHY）；卡片與 sidebar 都沒有「最近異常」或「診斷狀態」標記；sidebar 無 StatusLight；warning 卡只有 `ring-warn-bg` inset ring（#3A2B12 疊在 #111820 上幾乎看不見）；Event 列不可點。
- Why：值夜班的人只在意異常，但異常在被看到之前就消失了；多台並行診斷時必須靠記憶。
- Fix：sidebar 每列加 StatusLight 與右側 mono `crit 12s ago`（由 events 衍生）；卡片 footer 把 `updated just now` 換成診斷狀態 chip（Diagnosing 60% ／ Result · Warning ／ Cached ／ Failed）；warning 卡改 1px warn-border 全邊框；異常回 healthy 後保留 30 秒左緣 2px 狀態色條（純前端 latch，Event 列 ack 可清除）；Event 列改 button，點擊 selectMachine。
- 建議指令：`/impeccable clarify`、`/impeccable colorize`、`/impeccable harden`

**[P2] 1024 平板 TopBar 重疊，drawer 寬度策略僵硬**
- What：1024 寬時 search 被壓到約 44px，Pause 文字疊進搜尋框（違反產品約束「不得 UI 重疊」，截圖證實）；中欄被壓成單欄，右側 400px drawer 仍只顯示一句 idle 文案；手機 placeholder 截成 `Search ma`。
- Why：產品約束明文禁止；平板上主內容只拿到約 37% 寬度。
- Fix：寬度 <1280 時 drawer 預設收合、選台才展開；toolbar <640 時 search 改 icon button、點擊展開 overlay input；search 容器 `min-w-[160px]`，不足時整顆換 icon，不允許 flex 壓到重疊。
- 建議指令：`/impeccable adapt`

## Minor Observations

- idle chip `bg-elevated` 疊在 drawer 的 `bg-elevated` 上，chip 背景消失，Idle 變浮動文字。
- active 步驟點用 `animate-critical-pulse`，keyframe 光暈是紅色：藍點冒紅暈，語意錯用。
- Stale 徽章用 warn 配色，Fleet Health 的 stale 用中性 strong；同一狀態兩種語意色。
- `EventStrip.vue` 的 `toLocaleTimeString()` 輸出 `下午2:10:56`，應固定 24 小時制 `HH:mm:ss` mono。
- 5 張卡同時 `updated just now` 是 5 行重複雜訊；超過 2 秒才顯示才有資訊量。
- 單位 10px fg-subtle 在 22px 數字旁幾乎讀不到（偵測器 22 筆 undersized 的主體）；`mm/s` 與 `u/min` 只能靠猜。
- 中文放進 JetBrains Mono 走系統 fallback，中英混排字距與基線不齊；全站字型堆疊沒有 CJK 字族。
- 文案語言混用：UI 英文，drawer 有 `診斷進行中`、`中止診斷`、`推理過程`；違反 PRODUCT.md「UI 文案以英文為主」。

- 3.5% 白色格線幾乎不可見，是無效裝飾（偵測器 codex-grid-background）。
- sidebar 五項同一個 Boxes icon，不帶資訊。
- job meta 的 `Queue: diagnosis` 是常數，佔一整格。
- 手機 bottom-sheet 無 grabber；idle 時下半 60% 空白。
- 完成態 `推理過程` 摺疊鈕 12px subtle，可發現性低。

## Questions to Consider

1. 背壓比值如果是這個產品的心跳，為什麼它是一顆 pill，而不是整個監控台頂端那條會跳的心電圖？
2. `PREP → FORMING & BAKING → FULFILMENT` 已經是一條產線，為什麼主畫面是無序網格？改成 Argo CD resource tree 式的 stage 欄加連線，「致敬」才會從狀態點升級成拓樸語言。
3. 逐字串流要展示的是「token 在流動」還是「推理在成形」？若是後者，為什麼要讀 JSON？若是前者，為什麼不把 tokens/s 畫出來？
4. Copilot 一定要是常駐 400px 欄位嗎？閒置時用 28% 寬度換一句話。改成在卡片下方展開，或只在有任務時出現的 overlay，會不會更符合「一次只呈現選取那台」的狀態機？
5. 值夜班的人需要的是「現在」還是「剛才」？三秒後自己回 healthy 的 critical，介面該不該 latch 住直到有人 ack？這個答案決定網格、sidebar 與 Event Stream 的整個資訊架構。
